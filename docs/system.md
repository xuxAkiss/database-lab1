# 第一阶段系统说明

目标：登录用户创建并发布可配置问卷，经固定链接填写，保留提交历史，由创建者查看版本内最新答卷统计。实现不使用现成问卷框架或关系数据库。

## 组成与使用

Python/FastAPI 同步接口 + PyMongo + MongoDB 单节点开发复制集；Uvicorn 提供同源原生 HTML/CSS/JavaScript。业务持久化均在 MongoDB；源码、配置和运行日志属于本地工程文件。浏览器 sessionStorage 只保存提交重试键及版本/尝试元数据，不作为业务数据来源。

1. `/` 注册、登录；`/manage` 仅列自己的问卷。
2. 创建后添加题目/限制/规则，保存编辑修订，再发布。编辑保存不改变当前发布结构。
3. 分享 `/s/{token}`，登录后开始本版填写；自动保存显示结果，刷新恢复。返回修改及补答由服务器状态机控制。
4. 提交成功保留历史；允许重复时明确开始新空白填写。创建者从编辑区进入统计。
5. `/statistics/{survey_id}` 默认当前发布版，单题选择固定本次读取版本；点刷新重新读取当前版。关闭或到期仍可查看统计。

身份由 MongoDB 服务端会话确定，管理接口校验 owner_id；匿名不意味着免登录。统计无论匿名开关均省略身份，逐题独立排列填写内容，不输出可跨题关联的答卷行标识。主动填写的文字可能包含自述，不自动删改文本。

## 模块边界

- `backend/auth.py`：Argon2id、服务端 Cookie 会话、Origin/CSRF、权限依赖。
- `survey_models.py` / `surveys.py`：可配置结构校验、独立编辑稿、不可变发布版本、运行状态。
- `filling_engine.py` / `filling.py`：纯状态转移、草稿 CAS、来源图、事务提交和幂等。
- `statistics.py`：创建者鉴权、版本固定、最新答卷选择和单题汇总。
- `main.py`：应用、脱敏错误、健康检查和静态页面。

## 要求与选择的区别

教师要求见 `requirements-matrix.md`。账号去重取最新、完全匹配、连续跳转优先、连锁撤销、重新发布切版等是用户确认的业务选择，不声称教师指定这些实现。

实现默认值：用户名 NFKC/小写化 3–32 字符；密码12–128字符；8小时绝对会话；同源 Origin + CSRF；无自动规则时自由导航；可选空白不受最小限制；数字使用有限 IEEE-754 数值；文本按码点去除明确 White_Space 集后计数；关闭暂停草稿修改但允许读取；统计不展示百分比。详见各模块文档。

限制：本地开发配置不构成公网安全部署；没有账号限流、分页统计、导出、复杂图表或未知第二阶段功能。大规模统计受 MongoDB 聚合内存/文档大小和接口超时限制，未做容量压力验证。
